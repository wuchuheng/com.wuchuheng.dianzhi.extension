# Documentation Quality Rules

- Keep docs concise and operational.
- Prefer concrete commands, file paths, and gates over broad advice.
- Keep documentation scoped to the current project unless explicitly documenting external references.
- Use tree-style file diagrams when editing existing tree sections.
- Do not introduce unresolved placeholder markers.
- When docs define implementation work, include entry criteria, exit criteria, and verification commands.
